## Goal

A private golf app JF can play with family and close friends: 2–4 players in one
group, live shared scoring, GPS distance to the green, and a "Crazy Cards" chaos
deck that runs alongside the round.

**Done looks like:** JF and two mates finish a round at Trangie using nothing but
the app — scores syncing live between phones, yardages matching the course
markers, and cards played on each other — and the card wording has been rewritten
based on what actually happened.

Hard constraints that must never be broken: **$0/month forever**, no credit card,
no paid APIs, no betting or money features.

---

## What This Thing Does

An installable web app (PWA) at **https://crazygolfgame.web.app**. No app store,
no install — players open a link and add it to their home screen.

- **Accounts** — username + password, no email address
- **Rounds** — one player creates a round, others join with a 4-character code
- **Scoring** — each player enters their own score; live leaderboard ranked on to-par
- **Yardage** — GPS distance to the centre of the green, on a satellite hole map
- **Crazy Cards** — a deck dealt at the start of the round; players play cards on
  each other ("make them hit their next shot with eyes closed"). Honour-system:
  the app records what was played, the players enforce it

Currently one course: **Trangie Golf Club, NSW** — fully mapped and verified.

### Decisions worth not re-litigating
- **PWA, not native** — three known players don't need background GPS; avoids
  $99/yr Apple fees and UDID registration
- **Firebase over Supabase** — Supabase pauses free projects after 7 days idle
  with a 10–30s cold start, fatal for a fortnightly golf app
- **No Firebase Cloud Storage** — needs the paid Blaze plan. Avatars will be
  base64 in the user document instead
- **Leaderboard ranks on to-par, not strokes** — ranking on strokes puts a player
  who hasn't teed off top on zero
- **Cards are honour-system and timing is NOT enforced** — retroactive play is
  deliberately allowed (see Lessons Learned)

## Lessons Learned

### About this project
- **The scorecard is the safety net, not OSM.** Trangie's geometry was verified by
  comparing each mapped tee-to-green distance against the metres printed on the
  club's own card. That turned mapping from a trust exercise into a verifiable one.
  Use the same approach for any future course
- **A systematic small error is a sign of correct data.** All 18 holes mapped
  ~4 m short, consistently. That's the card measuring from the back tee markers
  while the centroid is mid-box, plus doglegs. Random mis-assignment would scatter
  both ways by much larger amounts
- **Cards are honour-system and timing is deliberately NOT enforced.** JF's ruling:
  play a card any time; the guide cutoff is the next player hitting, but the tee
  box stays open until the group leaves. Do not "improve" this by adding
  enforcement — it would kill the best moment in the game
- **The card text IS the mechanism.** Since nothing is enforced in code, a card's
  wording has to survive three people arguing on a tee. Validation refuses rules
  under 20 characters for exactly this reason

### Environment gotchas (will bite again)
- **ThreatLocker blocks the `.cmd` shims** that `npx`/`npm` generate for CLI
  packages. `npx firebase login` is refused outright. `node` is approved, so every
  Firebase script calls the JS entry point directly:
  `node node_modules/firebase-tools/lib/bin/firebase.js`. Use `npm run fb -- <cmd>`.
  **Do not "simplify" these back to `npx firebase`**
- **No Java on JF's machine**, and `firebase-tools` needs **JDK 21+** (not 17 —
  CI failed on that first). The Firestore emulator therefore only runs in CI
- **`sort` is blocked** in the Bash tool on this machine. Use node for sorting
- **Firebase rejects passwords under 6 characters.** JF specified `1234` for the
  admin reset; it is `123456` because `1234` is impossible. He accepted this but
  may want a different value
- Firebase web API keys are **public by design** and are committed deliberately.
  `firestore.rules` is what protects the data. A *service account* key would be a
  real secret — never commit one of those

### About working on this codebase
- **Parallel agents work, but only with a shared contract written first.** Three
  agents built Phases 3/4/5 simultaneously in git worktrees off an agreed data
  model in `src/lib/rounds.ts` and `src/lib/leaderboard.ts`. Without that they'd
  each have invented their own `Round` type
- **An agent found a real bug in the contract code:** `leaveRound` set a `left`
  flag that `joinRound` never cleared, so a player who left could never rejoin —
  they'd write their document, see no error, and stay invisible. Fixed, but it is
  a reminder that a second pair of eyes earns its keep
- **A killed agent does not lose its work.** Two agents were terminated mid-task by
  a usage limit; their files survived uncommitted in the worktrees and were
  recovered intact. Check the worktree before assuming anything needs redoing
- The repo's ESLint enforces **`react-hooks/set-state-in-effect`**. The pattern
  that satisfies it: tag state with the id it belongs to and resolve staleness on
  read, rather than clearing state inside an effect. Several files use this
- **Verify deploys by checking response headers, not the "Deploy complete"
  message.** A broad `**/*.js` cache rule once set `sw.js` to `immutable` for a
  year, which would have frozen every installed copy of the app permanently with
  no way to push a fix
